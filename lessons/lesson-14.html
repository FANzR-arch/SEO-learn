第十四课 · 阶段四 技术 SEO

递名单，认正版：帮引擎收好每一页

上一课学的是「拦」。这一课反过来学「帮」：用 sitemap 主动把重要页面递给搜索引擎，用 canonical 在一堆长得差不多的网址里指认「哪个是正版」。两件都是收录管理的基本功。

学完你能做什么
筛选应进入 sitemap 的规范网址；区分 canonical 与重定向；检查 Google 实际选择的规范页，而不把声明等同处理结果。
1 sitemap 是什么

一份「我觉得这些页面重要」的清单

sitemap（站点地图）是一个 XML 文件，列出你希望搜索引擎知道的网址。它替爬虫省事：不用完全靠链接一层层爬，也能发现那些藏得深、或链接少的页面。

sitemap.xml · 简化示例
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://yoursite.com/pour-over-guide</loc>
    <lastmod>2026-07-01</lastmod>
  </url>
  <url>
    <loc>https://yoursite.com/water-temp</loc>
  </url>
</urlset>
帮助发现 ≠ 保证收录
Google 说得明白：sitemap「帮助搜索引擎发现网址，但不保证里面所有项都会被抓取和收录」。它是「请查收这些页」的提示，不是收录的入场券——页面能不能进索引，还得看质量、重复度等因素。
2 sitemap 的取舍

放什么、不放什么，别写没用的字段

sitemap 是你给引擎的「重要页面推荐名单」，所以放的应该是你希望被收录的、规范的（canonical）页面。反过来，这些别放进去：

  • 加了 noindex 的页：你都不想收录它了，还推荐它，是自相矛盾；
  • 被 robots.txt 屏蔽的页、重复网址、非规范版本：会给引擎发混乱信号。
  • 重定向、404、410 的网址：常规推荐清单应列出最终返回正常内容、可以索引的网址；旧址迁移的处理另看实际方案。
两个字段别费心：priority 和 changefreq
老教程里常见 <priority>（重要度）和 <changefreq>（更新频率）两个标签。Google 官方多次确认它们不被使用——填了也白填。相比之下 <lastmod>（上次修改时间）会被参考，但前提是如实填写；如果每个页面都谎报「今天刚更新」，Google 会慢慢不再相信它。

先看网址实际返回了什么

HTTP 状态码是服务器对请求的答复，比页面上写「成功」或「找不到」更底层。筛选 sitemap 前，先分清这些常见情况：

状态含义与处理
200正常返回内容，但不保证收录；还要检查正文、noindex 与规范化。
301 / 308永久搬到新网址。站内链接与常规 sitemap 更新为最终网址；不要无限跳转或都跳到无关首页。
404 / 410页面不存在 / 已移除。无相关替代内容时正常返回它们，不必把每个删除页都重定向。
soft 404服务器返回 200，页面却为空、报错或缺少应有内容，Google 可能当作软 404 排除。修复内容，或对确已删除页面返回正确状态。
3 canonical 认正版

同一份内容有好几个网址，指一个「正版」

很多时候，同一个页面能通过好几个网址打开：

下面这些，其实是「同一篇文章」
https://yoursite.com/pour-over-guide
https://yoursite.com/pour-over-guide?ref=weibo     # 带分享跟踪参数
https://yoursite.com/pour-over-guide?utm=ad         # 带广告参数
https://www.yoursite.com/pour-over-guide            # 带 www

它们是不同网址，但可能被识别为重复或近似内容。Google 会在这组网址中选择一个规范网址（canonical URL）。你可以用 rel="canonical" 声明偏好，帮助整合链接等信号、减少重复抓取；Google 仍会综合其他信号决定。普通重复内容也不等于自动受到「重复内容处罚」。

在每个变体页的 <head> 里指向正版
<link rel="canonical" href="https://yoursite.com/pour-over-guide">
  • canonical 是「信号」不是「命令」：它告诉 Google 你的偏好，但 Google 会综合判断，最终可能选别的版本作正版；
  • 推荐「自引用」：连正版页自己也放一条指向自己的 canonical，是 Google 推荐的做法，不是错误；
  • 目的要一致：canonical 用于重复或高度相似内容的规范化，noindex 用于排除当前页。不要用 noindex 代替规范化，也不要把不相关页面都 canonical 到首页；
  • 统一入口：sitemap、站内链接与 canonical 尽量都指向同一个可索引网址。参数页若内容实际不同（如不同语言或筛选结果），先判断是否真的重复。
canonical 不会把访客送走
旧网址已经永久搬家、不必继续单独访问时，通常使用 301 或 308 永久重定向。canonical 保留原网址可访问，只提供规范化信号。改完后在 Search Console 网址检查中比较「用户声明的规范网址」与「Google 选择的规范网址」，后者须等重新抓取与处理。

5 随堂自测

点一点、填一填，检查你会了没

练 真实页面练习 · 20 分钟

把同一篇内容的入口对齐

  1. 选 5 个真实网址，包含一个规范文章、一个带跟踪参数的版本、一个重定向旧址、一个 noindex 页和一个新页；没有网站时用示例拟表，不实际改线上规则。
  2. 记录状态码、是否可抓取、是否允许索引、canonical 指向和是否在 sitemap 中。可用浏览器开发者工具的 Network（网络）面板查看文档响应；没有权限时只观察公开页面。只把期望被索引的规范内容页列入常规 sitemap。
  3. 检查文章内链是否指向规范网址。有 Search Console 权限时提交或查看 sitemap 状态，并检查一个重复版本实际选择的规范页。
验收
交付 5 行网址表，解释每项取舍。规范目标可访问、内容匹配；sitemap 与内链没有误指向旧址或参数版；lastmod 对应实质内容更新。声明与 Google 实际选择不一致时记录为待排查，不宣称 canonical 已强制生效。
本课要点
  • sitemap 帮助发现页面，但不保证收录；只放重要、可收录、规范的网址；
  • priority 和 changefreq Google 不使用；lastmod 有用，但要如实填；
  • canonical 声明规范网址偏好，用于重复或近似内容，不会让访客跳转；
  • 它是信号不是命令；保持内链与 sitemap 一致，检查 Google 实际选择；永久搬家另用重定向。
